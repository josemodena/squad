# Squad 0.4.5 — owned blockers and explicit continuation

A board card could look actionable while waiting for authority, genuine input or
missing metadata. Readiness now exposes structured blockers with an owner, exact
next action, user-action flag and claimability. Known blockers prevent delivery
claims even when scope is agreed and quota policy is unrestricted.

- `squad next` lists dispatchable work, bounded PM repairs and named waits.
- User requests get an orange **🟠 needs-your-action** label and a readable request:
  what to do, why and the PM's recommendation. Existing Status is preserved.
- `blocker visibility` adds Labels to existing Project views, backed by a fresh
  snapshot and write journal. It does not rebuild options or add a Status column.
- Missing estimates, roles and stages can be repaired through `repair-claim` using
  the configured PM model, ordinary ownership locks and pause/capacity checks.
- Delivery claims require an explicit input/authority/brief assessment.
- A finished job cannot be acknowledged without an owned handoff. Recovery records
  expose the last captured blockers, owners and actions with a timestamp.
- Readiness reads batch native prerequisites and labels rather than fetching
  dependencies separately for each active issue.

Update both plugins and the CLI, then use a fresh Administrator session. Existing
finished jobs need a handoff before ack; existing claim scripts must supply
`--readiness FILE`. Follow the [blocker and continuation guide](https://github.com/josemodena/squad/blob/v0.4.5/docs/guides/blockers.md).

The Administrator must continue internal work and refresh readiness after each
handoff. External input, capacity and user decisions can still require a legitimate
wait; the fix makes that wait explicit and owned. CLI assessments are recorded
judgements, not automatic proof of arbitrary product evidence or user authority.

Validation covers missing estimates, independent metadata repair, external input
and authority blockers, unchanged Status, duplicate-claim prevention, mandatory
handoffs, blocker journals, malformed metadata and batched readiness reads.
Existing backup/option-identity and release checks remain in the full suite.
