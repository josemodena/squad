# Squad 0.5.0 — PM authority, reply recovery and durable learning

The Administrator owns continuity. When agreed work cannot proceed, it assigns
resolution to the Project Manager. The PM resolves delivery problems within
explicit delegation and is the sole owner of escalations to the user.

- `squad pm-claim` permits bounded diagnosis without authorising blocked delivery.
- New user requests require recorded PM provenance, an authority boundary and
  consequences of waiting. Existing blockers remain readable and can be reassessed.
- A deterministic observer imports GitHub replies while agents are stopped.
  Pagination, deduplication and rate-limit backoff avoid repeated paid checks.
  Replies remain evidence until a PM verifies identity, scope and prior decisions.
- Every claimed agent receives a durable role/authority/context packet. Both plugins
  ship six job descriptions with responsibilities, accountabilities and success criteria.
- Private, project-scoped Git stores retain decisions and lessons. Only reviewed,
  committed records enter startup context; lessons never grant new authority.
- Review labels use REST instead of the deprecated Project Classic query path.
- The README now introduces decision ownership, SDD and recovery in appropriate
  sections, with a linked guide for new users.

Update the plugins and use fresh sessions after checkpointing active work. Set
`decision_makers` to the intended GitHub logins. Run `squad ready`, then
`squad inbox poll --force`; register older requests with `inbox watch --since`
when their original dates are not in cached readiness. User pauses are preserved.
No board option or Status migration is required.

See [decisions and learning](https://github.com/josemodena/squad/blob/v0.5.0/docs/guides/decisions-and-learning.md)
and [role descriptions](https://github.com/josemodena/squad/blob/v0.5.0/docs/roles/README.md).

Validation covers stopped-session reply recovery through PM assessment and delivery
eligibility, edited and duplicate replies, pause/capacity gates, incomplete API
reads, bounded backoff, PM request provenance, reviewed-memory isolation and the
existing board backup/restore and native-session regression suites. The observer
covers issue comments; it does not infer decisions from reactions or other chat systems.
