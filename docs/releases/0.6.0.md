# Squad 0.6.0

Talk directly to the Project Manager for planning, delivery and retrospectives.
The Administrator role is retired. Deterministic CLI scripts handle routine
tracking, readiness, ownership and safe changes; the PM handles decisions and
native technical subagents.

## Changes

- `squad start` opens or focuses the main PM tab in Zellij. Codex uses its managed
  App Server thread; Claude Code uses a captured, resumable native PM session.
- Interactive entry and external recovery use the same PM ownership. Repeated
  starts focus the existing session. Ambiguous starts refuse a duplicate.
- PM startup verifies captured session identity. Loading a skill cannot silently
  turn a Luna session into an Astra PM or substitute another model.
- Codex Engineer and Engineering Reviewer use GPT-6.1 Sol at **medium effort**.
  New claims record the effort, and bind rejects missing or mismatched effort.
  Existing jobs retain their recorded settings.
- The PM performs bounded metadata repair and delivery resolution in its own
  session. Technical work still uses fresh native subagents and independent review.
- README, both plugin guides, role contracts, requirements, CLI reference and
  migration instructions now describe the same five-role workflow.

## Upgrade

Update the marketplace/plugin and the checkout providing the `squad` command.
Checkpoint and reconcile existing workers before replacing the old coordinator.
A running session cannot change its model just because the plugin was updated.

Follow the [PM migration guide](https://github.com/josemodena/squad/blob/v0.6.0/docs/guides/pm-migration.md).
Codex requires rebuilding its managed adapter and an idle rollover of the old
thread. It uses systemd and Go even when the optional recovery timer is disabled.
Claude users should close reconciled legacy Administrator/meeting sessions before
starting the new PM. See [launcher setup](https://github.com/josemodena/squad/blob/v0.6.0/docs/guides/meetings.md).

No board migration is needed. Existing Status values, option IDs, snapshots,
checkpoints, pauses, approvals and quota policy remain intact. Historical role
options can remain on the board without being assigned to new work.

## Validation and limits

Validation includes the Python runtime and board-backup suites, shell fixtures,
Go App Server tests with the race detector, and real Zellij launch/focus checks
using throwaway projects and fixture model CLIs. Tests cover explicit model and
effort, wrong-session rejection, duplicate/ambiguous launch prevention, project
isolation, exact native completion and preservation of pauses.

The terminal checks do not perform paid model inference or exhaust a subscription.
Linux remains the supported platform. Claude recovery retains its terminal-level
limits and one configured recovery project per OS user. The gateway and scripts
cannot create provider capacity or override a deliberate user pause.
