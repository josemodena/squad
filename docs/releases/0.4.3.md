# Squad 0.4.3 — preserve Project data and back up board changes

This release fixes a data-loss bug: migration and Sprint-option creation could
replace single-select options without their original IDs, clearing item values.
Existing option IDs, names, colours and descriptions are now retained. Unchanged
option lists are not rewritten.

## Board protection

- Timestamped snapshots committed to a private local Git repository before board
  migration, option changes and item-field writes.
- Separate histories and locks per GitHub host, owner and Project number, including
  when multiple projects share a backup base.
- Complete paginated API-visible exports of fields, active/archived items, values
  and view configuration; partial snapshots cannot authorise writes.
- Restore dry-run with a complete diff and blockers. Apply requires the exact
  project ID and the confirmation hash from the reviewed board state.
- Bounded rate-limit backoff, budget preflight and per-write recovery journals.

## Update and recovery

Update both the plugin and any checkout-backed CLI, then start a fresh harness
session. Do not rerun migration from an old session holding an older plugin path.
Take `squad board snapshot` before repairs. See the
[backup and restore guide](https://github.com/josemodena/squad/blob/v0.4.3/docs/guides/board-backup.md)
for commands, retention and multi-project storage.

This release cannot reconstruct data lost before backups existed. Deleted option
IDs require a reviewed mapping to current valid IDs. View grouping/sorting can be
exported but are not writable through the documented view update input; unsupported
differences block a full restore. GitHub has no whole-board transaction: an outage
mid-restore can leave partial writes, recorded in the journal for reconciliation.

## Validation

Fixtures reproduce the legacy clearing behaviour and verify identity-preserving
updates. Both real plugin init entry points run twice against a stateful fixture
without changing existing item values or views. Tests cover cleared-status restore,
view-filter restore, confirmation, incomplete snapshots, multi-project isolation,
nested pagination, bounded rate-limit retries and interrupted-write journals.
Queries were validated offline against GitHub's published GraphQL schema.

A read-only live export encountered an exhausted GraphQL limit and stopped before
saving a snapshot or changing the board. Live restoration was not performed.
