# Getting help

Read the [quickstart](docs/getting-started/quickstart.md),
[requirements](docs/getting-started/requirements.md), and
[troubleshooting guide](docs/guides/troubleshooting.md) first.

For a bug, use the GitHub bug-report form with harness/version, OS, reproduction
steps, expected behaviour and redacted diagnostics. For an improvement, explain
the coordination problem and who benefits. Contributions to portability and live
harness validation are especially useful.

Never include private project names, credentials, full settings, runtime archives
or raw transcripts. Use SECURITY.md for security-sensitive reports. Support is
best effort; there is no service-level agreement.
